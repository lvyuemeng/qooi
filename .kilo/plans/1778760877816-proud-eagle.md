# Plan: Decouple Strategy Selection, Clean Strategy Package, and Rationalize Signal Features

## Current Findings

### Strategy package

Current `src/qooi/strategies/` contains both the new composable layer and old monolithic strategy files:

- Keep/active composable layer:
  - `__init__.py`
  - `compose.py`
  - `conditions.py`
  - `features.py`
  - `specs.py`
  - `flow_pipeline.py` if retained as reusable OFI/regime feature helpers
  - `portfolio.py` if portfolio allocation remains in scope
- Outdated monoliths to remove:
  - `ema_pullback.py`
  - `ema_pullback_v2.py`
  - `momentum.py`
  - `momentum_1h.py`
  - `rsi_reversion.py`

These old files embed exits/circuit breakers inside signal generation and are tightly coupled to strategy names/timeframes, which conflicts with the composable four-layer design.

### Strategy fixation still exists in `core/config.py`

`core/config.py` currently fixes a strategy on each pair through `OkxSignalConfig.strategy`. That couples asset/execution config to research-time signal selection and leaks strategy identity into:

- `BacktestExecutor.run()` via `compute_signal_frame(df, pair.okx.strategy)`
- `process_bar()` basket lookup/open IDs via `pair.okx.strategy`
- `scripts/trade.py` live signal selection
- OKX bot descriptions, reports, state tests, and labels

Decision:

- Remove strategy identity from `OkxSignalConfig` and `PairConfig` as a required/fixed property.
- Treat strategy selection as orchestration input: a `StrategySpec` or canonical strategy name passed to backtest/live runs.
- Use a runtime `strategy_id` label only where basket/state/report identity needs a string.
- Keep `OkxSignalConfig` strictly about OKX signal bot execution settings (`tp_pct`, `sl_pct`) and not signal research identity.

### Compatibility names still exist

`resolve_spec()` still accepts old names through `StrategyAlias`:

- `momentum_1h`
- `rsi_reversion`

The user explicitly wants no backward compatibility. These should be removed. Canonical strategy names should be generic and composable:

- `momentum_burst`
- `rsi_bounce_reversion`
- `flow_pipeline` only if OFI/regime remains supported

### `exchange/backtest.py`

`src/qooi/exchange/backtest.py` is not imported anywhere except itself according to search. It contains old pair-spread and portfolio backtest utilities, while the active single-asset pipeline uses `core.executor.BacktestExecutor` and `core.styles`.

Decision:

- Do not keep this file in `exchange/`; backtesting is not exchange I/O.
- If pair-spread/portfolio backtesting is still desired, move the useful pieces into `core/portfolio_backtest.py` or `research/portfolio_backtest.py` in a later step.
- For this cleanup, remove `src/qooi/exchange/backtest.py` if no tests/scripts require it.

### `exchange/indicator.py` overlaps with `strategies/`

`src/qooi/exchange/indicator.py` is still necessary right now because `add_indicators()` is used by:

- `BacktestExecutor`
- `scripts/trade.py`
- `core.indicators` / flow pipeline tests
- data tests

But the location is conceptually wrong: indicators are feature engineering, not exchange I/O. There is also conceptual overlap with `strategies/features.py`:

- `exchange/indicator.py` computes generic technical indicator columns (`ema_20`, `rsi_14`, `atr_14`, `adx_14`, Bollinger, VM swing).
- `strategies/features.py` computes strategy-composition features (`momentum_return`, `trend_bars`, session hour, price structure, volume average).
- `strategies/conditions.py` turns precomputed columns into signal/filter predicates.

Decision:

- Move indicator precomputation out of `exchange/` because exchange code should only fetch/normalize market data.
- Put technical indicator precompute under strategy ownership, preferably `src/qooi/strategies/indicators.py` for this repo’s current package shape.
- Keep this wire:
  - market data fetch returns raw OHLCV only
  - indicator precompute adds reusable market features
  - strategy spec feature functions add spec-specific derived columns
  - condition builders define entry/filter/exit expressions
  - `compute_signal_frame()` orchestrates this and returns `signal`
- Do not keep a long-term import shim in `exchange/indicator.py` unless needed for a migration step; tests should import from the new location.

### `market.py` / `store.py` cache path for longer data

Current behavior:

- `MarketData.candles(..., cache=True)` fetches recent bars only (`get_candlesticks`, typically max 300) and merges into `data/cache/{SYMBOL}_{TF}.parquet`.
- `MarketData.candles_range()` fetches deeper paginated history via backend `fetch_ohlcv_range()`.
- `CacheStore.refresh(inst_id, bar, days, min_bars)` uses `candles_range()` for deep history, then merges recent candles.
- Scripts/backtest currently use fixed `data/cache/{sig_symbol}_1H.parquet`, which is not robust for multiple timeframes/assets.

Issues for XAU/intermediates:

- OKX instrument candles for newly listed swaps may be short because the swap listing date can be recent.
- Docs note that OKX index candles can predate swap listing, but `MarketData` currently does not expose index candle retrieval.
- For XAU, signal data likely needs index candles (`XAU-USDT`) while execution may use swap (`XAU-USDT-SWAP`) if available.

## Implementation Goals

1. Remove strategy fixation from `core/config.py`.
2. Make strategy selection an explicit orchestration input, not pair config.
3. Move technical indicator precompute from `exchange/indicator.py` into strategy-owned feature code.
4. Remove outdated strategy files.
5. Remove strategy backward compatibility names.
6. Keep only composable strategy specs and reusable feature/condition modules.
7. Update configs/tests/scripts to use explicit runtime strategy selection.
8. Decide/remove `exchange/backtest.py`.
9. Add asset coverage for BTC and XAU/intermediates for robustness testing.
10. Improve cache resolution for longer data across multiple symbols/timeframes.
11. Update docs with missing features and data-cache workflow.
12. Validate with ruff, ty, pytest, and backtests over all configured assets.

## Step 0: Remove Strategy Fixation From Pair Config

Update `src/qooi/core/config.py`:

- Delete `StrategyName` from this module.
- Remove `strategy` from `OkxSignalConfig`.
- Update `OkxSignalConfig` docstring so it describes only execution-layer OKX signal bot settings.
- Update `PAIRS` so `OkxSignalConfig(...)` only includes `tp_pct` and `sl_pct`.

Introduce strategy selection outside pair config:

- In `scripts/backtest.py`, choose the strategy via CLI/default, for example `--strategy momentum_burst`.
- In `scripts/trade.py`, choose the strategy via a module-level default or CLI/env, for example `QOOI_STRATEGY=momentum_burst`.
- In `BacktestExecutor.run()`, accept a `strategy` or `spec` argument and compute `strategy_id = spec.name` or the canonical string.
- In `process_bar()`, accept `strategy_id: str = "default"` as an explicit argument for basket lookup/open, instead of reading `pair.okx.strategy`.

Update dependent code:

- `core/executor.py`: pass the selected strategy to `compute_signal_frame()` and pass `strategy_id` to `process_bar()` and hedge basket creation.
- `core/__init__.py`: use the passed `strategy_id` for `BasketBook.for_pair()` and `book.open()`.
- `core/state.py`: load soft basket state by symbol plus externally provided strategy IDs, or use `default` when strategy identity is not available. Prefer making strategy state loading accept `(pair, strategy_id)` from orchestration rather than pulling from config.
- `exchange/trading.py`: OKX bot description should not need a strategy name from config. Use a generic description or accept an optional label from live orchestration.
- `core/evaluate.py` and tests: labels should use explicit strategy labels from the runner, not pair config.

Rationale:

- A pair describes an instrument and execution sizing, not how signals are researched.
- The same asset can be tested across multiple specs without cloning `PairConfig`.
- Basket/state identity still gets a strategy label, but that label belongs to the run context, not the canonical asset config.

## Step 4: Improve Long-History Cache Workflow

Keep `MarketData` as transport/facade and `CacheStore` as persistent cache manager.

Required improvements:

1. Standardize cache path generation.

   - `MarketData._cache_path()` uppercases timeframe and symbol.
   - `CacheStore._path()` currently does not normalize slash or uppercase consistently.
   - Create one shared cache-path helper or make `CacheStore._path()` match `MarketData._cache_path()` exactly.

2. Prefer `CacheStore.refresh()` for deep history.

   - Backtests should not depend on `MarketData.candles(cache=True)` because it only accumulates recent 300-bar calls.
   - Use `CacheStore.refresh(inst_id, bar, days, min_bars)` for long backtest data.

3. Add a cache warmup script or command.

   Suggested script: `scripts/cache_data.py`

   Usage:

   ```bash
   uv run python scripts/cache_data.py --research --days 1000 --min-bars 5000
   uv run python scripts/cache_data.py --symbol BTC-USDT --bar 1H --days 1000 --min-bars 5000
   uv run python scripts/cache_data.py --symbol XAU-USDT --bar 1H --source index --days 1000
   ```

4. Add OKX index candle support for XAU/intermediates.

   MarketData currently exposes instrument candles only. Add one of:

   - `MarketData.index_candles(inst_id, timeframe, limit, cache=False)`
   - `MarketData.index_candles_range(inst_id, timeframe, since, limit)`
   - backend methods wrapping OKX `get_index_candlesticks`

   For XAU:

   - use `XAU-USDT` index candles for signal research when `XAU-USDT-SWAP` history is too short.
   - keep execution symbol separate from signal symbol.

5. Cache metadata.

   Add or document cache metadata fields:

   - source: `instrument`, `index`, `ccxt`
   - exchange: `okx`, `lbank`, etc.
   - symbol
   - timeframe
   - first/last timestamp
   - row count

   Could be a sidecar `data/cache/manifest.json` later. For now, `CacheStore.list_cached()` should be enough if path names are consistent.

## Step 6: Move Indicator Precompute Out of `exchange/`

Retain indicator functionality because it is required by the active pipeline, but move ownership to strategies.

Recommended implementation:

- Create `src/qooi/strategies/indicators.py` with the current functions from `exchange/indicator.py`:
  - `sma`
  - `ema`
  - `rsi`
  - `atr`
  - `adx`
  - `bollinger_bands`
  - `volatility`
  - `vumanchu_swing`
  - `add_indicators`
- Update imports in:
  - `core/executor.py`
  - `scripts/trade.py`
  - `core/indicators.py` if retained
  - `tests/test_data.py`
  - `tests/test_backtest.py`
- Delete `src/qooi/exchange/indicator.py` once imports are updated.
- Do not keep an `exchange.indicator` shim unless this repository has external consumers that are not visible in tests.

Signal and filter wire:

- `MarketData` and `CacheStore` return normalized OHLCV only.
- `strategies.indicators.add_indicators()` adds generic reusable technical columns.
- `strategies.features` adds strategy-specific derived columns required by specs.
- `strategies.conditions` contains reusable entry/filter/exit expressions over columns.
- `StrategySpec.filters` gates entries only; it should not mutate feature columns.
- `StrategySpec.entries` defines directional entry rules.
- `HoldPolicy.exit_when` defines signal-level flattening; basket/recovery/dynamic exits remain in core layers.
- `compute_signal_frame()` should become the orchestration point that ensures precompute is applied before spec evaluation, so callers do not need to remember `add_indicators()` separately.

Implementation note:

- Today callers manually do `add_indicators(df)` before `compute_signal_frame()`.
- Prefer changing `compute_signal_frame(df, spec_or_name, precompute=True)` or unconditionally applying missing indicator columns inside `compute_signal_frame()`.
- Avoid double-computation by only adding missing columns or keeping `add_indicators()` idempotent enough for repeated calls.

## Step 7: Missing Features Still Not Implemented

Architecture / strategy:

- Signal confidence/strength output is missing.
- Strategy specs are not yet selected/configured independently from pair config in the active runners.
- Closed-bar discipline is not explicit in API.
- Circuit breaker/cooldown is not yet a composable spec component.
- `flow_pipeline` is still special-cased rather than a normal `StrategySpec`.
- Indicator precompute is still manually wired by callers instead of guaranteed by `compute_signal_frame()`.

Basket layer:

- Magic/client order id per basket is missing.
- Basket group semantics for hedge recovery are incomplete.
- Partial close / scale-out action type is missing.

Recovery layer:

- Hedge lacks combined group PnL unwind.
- `breakeven_atr` remains unused unless implemented.
- Grid sizing policy needs alternatives: fixed add, linear add, capped multiplier.
- Recovery state ownership between decision and execution should be fully documented/test-enforced.

Dynamic PnL layer:

- Basket-level total profit target is missing.
- Recovery breakeven exit is missing.
- Live global drawdown stop is incomplete.
- Time/trailing exits may not map cleanly to OKX signal bot; direct TradeAPI path likely needed.

Data/research:

- No automated robustness sweep across assets/timeframes.
- No cache warmup CLI.
- No index candle path for XAU/intermediates.
- No manifest/metadata for cache provenance.

Live parity:

- `LiveExecutor` still prints several action kinds instead of placing all real orders.
- OKX position mode/order sizing details need integration tests or dry-run mocks.
